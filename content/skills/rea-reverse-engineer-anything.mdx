# REA reverse-engineer-anything

This skill teaches an agent to investigate a shipped artifact with REA and to
keep observations, inferences, and unknowns separate. Use it when an answer
depends on packaged code, decompilation, or requested runtime evidence. Skip it
for ordinary architecture analysis of a complete source repository.

## Installation

Use the install command above to fetch the authored skill folder and its
reference guides. The source download is the entire REA repository archive,
not a ready-to-upload skill package. Skill installation does not install REA,
register its MCP server, or provide analysis engines.

Follow the upstream installation guide to configure REA for your client. For
configuration changes, the skill uses doctor and a setup dry-run to expose the
actual proposed paths and backups before applying changes. Native analysis
requires a separately configured engine. Static JavaScript analysis does not
require Hopper, Ghidra, or IDA.

## Workflow

Provide a local artifact and a specific question, such as: "Which modules and
IPC handlers implement search in this extracted Electron application?"

The skill routes JavaScript/Electron trees to application analysis and native
binaries to the selected native provider. It reads relevant reference guides
only when needed, preserves artifact identity and source locations, and checks
whether the available evidence supports each conclusion. Runtime observation
is a separate choice when static evidence cannot answer the question.

The CLI fallback shown above returns an Evidence record directly. Inspect the
application graph, source-bound findings, limitations, and unknowns before
making claims about behavior. A successful static scan does not establish that
the application was executed or that MCP is connected.

## Verification Scope

On 2026-10-10, Codex followed the documented CLI fallback on a local Electron
fixture using published rea-agents@6.1.0. It returned artifact identity,
JavaScript module/import information, IPC observations, and limitations.
The same JavaScript workflow was also exercised through an MCP SDK stdio client.

Skill discovery with skills@1.7.1 found reverse-engineer-anything, and a separate
Cursor-targeted installation copied SKILL.md and all five reference guides
into an isolated project. That installation check is not a Cursor agent-host
execution, so testedPlatforms lists only Codex. These checks do not establish
new native-provider verification, automatic skill activation, or every
capability described by a newer skill from repository main. Use the connected
server's actual catalog and pin versions when reproducibility matters.
